# Architecture

AgriCredit Agent helps a local agricultural extension officer decide whether a smallholder household can realistically service a proposed input package on credit. It produces an evidence-cited **draft** and stops. Only a named officer can release it, and the release is bound to the exact draft they approved.

```
 Officer dashboard (Streamlit) / CLI
        │ start(case)                      ▲ draft + interrupt          │ approval (human only)
        ▼                                  │                            ▼
 LangGraph state machine ──MCP stdio──► agricredit-mcp (ours, Python SDK 2.x) ──► SQLite (synthetic data, approvals, outbox)
        │            └─────MCP stdio──► @modelcontextprotocol/server-filesystem (official) ──► fs_mcp_root/{policy,evals,audit_exports}
        └── HTTP ──► Qwen instruct model (Ollama / OpenAI-compatible, local)
 Every tool and LLM call ──► logs/tool_calls.jsonl     Lifecycle, approvals, releases ──► logs/audit_events.jsonl
```

**1. Agent shape.** One stateful agent with a fixed investigation order and model-chosen parameters. The workflow order is code, because an underwriting checklist should not depend on what the model feels like doing. The Qwen model does three jobs: it plans the investigation (look-back windows, which alternate market to try if data is stale, which risks to scrutinise), it reads the household notes as data, and it writes the officer-facing explanation. It never computes a figure, never selects the recommendation type, and cannot approve anything.

**2. Graph and state** (`agent/graph.py`). `load_case → validate_data → plan_investigation → get_household_evidence → get_weather_evidence → get_market_evidence → quantitative_assessment → contradiction_check → evidence_sufficiency → draft_advisory → human_approval (interrupt) → release | terminate → finalize`. Any node can route to `refuse`, which drafts nothing. State is a typed dict checkpointed by LangGraph. MCP connections are opened per graph segment, so a case waiting on an officer holds no processes open.

**3. Our MCP server: `agricredit-mcp`** (`mcp_server/server.py`). Seven tools, each with strict Pydantic validation and MCP read-only/action annotations: `get_credit_case`, `get_household_case`, `get_weather_signal`, `get_market_signal` and `assess_serviceability` (read); `draft_credit_advisory` (action: stores a draft, sends nothing); `release_advisory_after_approval` (action: gated release to a sandbox outbox). Anticipated failures return machine-readable codes (`NOT_FOUND`, `UNAVAILABLE`, `INVALID_INPUT`, `REFUSED`) that the graph routes on. Every evidence item and assessment the server emits carries an HMAC tag. `draft_credit_advisory` rejects anything unsigned or altered, and independently re-derives the policy decision, refusing a recommendation more permissive than the evidence supports. A jailbroken model or a buggy node therefore cannot inject numbers or upgrade a recommendation.

**4. Borrowed MCP server.** The official `@modelcontextprotocol/server-filesystem` (pinned 2026.8.31 in `package-lock.json`), maintained by the MCP project, rooted at `fs_mcp_root/`. The agent uses it to read the decision policy (`policy/agent_policy.json`) and to write a per-run audit summary (`audit_exports/`). The eval harness uses it to read its fixtures. Secure path handling, symlink resolution and allow-listing are generic, security-sensitive and already done well upstream: it refuses `/etc/passwd`, as eval E17 shows. Reimplementing that inside a credit server would add attack surface and no agricultural value, so `agricredit-mcp` exposes no file tools.

**5. Open-weight model.** Default `qwen2.5:7b-instruct` via Ollama (`.env`). That size is the practical balance for an extension office: reliable JSON planning and instruction following, and it runs on an 8 GB GPU or CPU-only with ~8 GB RAM at Q4. `openai_compatible` serves the same model from vLLM or llama.cpp, and `qwen3:8b` works with thinking switched off. No proprietary model is used or required. Every LLM call is logged with a prompt hash, backend and model ID. A deterministic `stub` backend exists for CI and is labelled "NOT an LLM" wherever it appears.

**6. Quantitative risk model** (`risk/`). Finance is plain arithmetic in `financial.py`: revenue, gross margin, cash available for debt service (the financed package is not double-counted), debt service, repayment capacity, DSCR, and four stress scenarios (−20% yield, −10% price, combined; both configurable). Probability of default comes from a calibrated logistic regression over 18 features (repayment, yield, farm, market, climate, financial). It was benchmarked against calibrated gradient boosting with 5×3 repeated cross-validation; the two tie on AUC, so the explainable model is used (`data/model_card.json`). Data-quality signals such as record age are enforced by the policy gate, not fed to the model: they carry no outcome signal in synthetic training data, and an early version learned a spurious "older record, lower risk" coefficient. The recommendation type comes from the deterministic policy in `policy.py`, with thresholds in the policy file.

**7. Human approval gate** (`approval/gate.py`). Approvals are recorded only through the officer interface; no MCP tool can create one. An approval binds officer ID and name, decision, timestamp, recommendation hash, evidence version and model version. Release re-derives everything from the database and blocks on any failed check: approval missing or not matching the stored record, not an APPROVE, wrong case, unregistered officer, expired (72 h default), already consumed (replay), hash mismatch, recommendation changed, evidence changed, or model version changed (configurable). The hash covers the narrative, so the officer approves the exact text that would be released.

**8. Audit trail.** `logs/tool_calls.jsonl` holds one record per MCP and LLM call: event ID, run ID, case ID, timestamp, agent node, server, tool, attempt, sanitised input, output, latency, success, error, cited source IDs and model version. Household free text is never logged, only a hash. `logs/audit_events.jsonl` records run start and finish, refusals, drafts awaiting approval, officer decisions, releases and blocked releases. Each run also writes a summary through the filesystem MCP server.

**9. Failure recovery.** Tool calls get bounded retries (policy: two attempts) on `UNAVAILABLE` only. Weather outage: retry once, then a policy-permitted cached observation marked stale with reduced confidence; if it is older than 21 days, no seasonal recommendation. Stale market price: one alternate market centre; if that is stale too, REQUEST_MORE_EVIDENCE and no price is assumed. Conflicting market feeds: never averaged or picked; REQUEST_MORE_EVIDENCE listing both values. Missing repayment history or unknown household: request evidence, or refuse with no draft. Injection-like household notes: flagged, withheld from the model, shown to the officer as a warning. LLM unavailable or narrative citing figures absent from the evidence: deterministic template, with a warning on the draft.
